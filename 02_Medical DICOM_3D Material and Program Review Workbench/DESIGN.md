# DESIGN.md

# 胸部 X 光肺炎异常检测：小样本迁移学习方案

## 1. 任务定义

本项目选择胸部 X 光肺炎异常检测作为主任务，具体实现为图像级二分类。

输入是一张胸部 X 光图像，模型输出该图像属于 `NORMAL` 或 `PNEUMONIA` 的预测概率和最终类别。项目使用少量公开、脱敏的胸部 X 光图像完成一个可运行、可检查的 baseline，重点验证数据读取、模型推理、训练和评估流程是否成立，而不是追求完整规模训练或临床级性能。

模型结果仅用于算法研发、工程验证和课程任务展示，不用于真实临床诊断、治疗或患者决策。

---

## 2. 数据

### 2.1 数据类型

当前使用已经下载到本地的公开胸部 X 光数据集，本地目录名为：

```text
chest_xray/
```

当前任务使用两个图像类别：

```text
NORMAL
PNEUMONIA
```

影像已经完成脱敏处理。

具体的数据集公开下载页面、原始发布方和许可条件需要以实际下载来源为准，在最终提交版本中补充，不对当前未提供的信息进行推测。

---

### 2.2 原始目录结构

保留数据集原始结构：

```text
chest_xray/
├── train/
│   ├── NORMAL/
│   └── PNEUMONIA/
├── val/
│   ├── NORMAL/
│   └── PNEUMONIA/
└── test/
    ├── NORMAL/
    └── PNEUMONIA/
```

本项目不重新建立新的 train、val、test 目录，也不移动原始图片。

---

### 2.3 小样本使用方式

由于任务重点是算法设计和工程验证，训练阶段只需要使用少量数据。

默认从原始 `train` 中固定抽取：

```text
NORMAL:     300
PNEUMONIA:  300
```

合计约 600 张训练图片。

样本数量可以通过配置调整。如果 CPU 性能有限，可进一步降低到每类约 200 张。

抽样时使用固定随机种子，并将被选中的相对路径保存到：

```text
configs/train_subset.csv
```

这样可以保证：

- 原始数据完全不被修改；
- 每次实验使用相同的训练图片；
- baseline 和改进模型之间可以公平比较；
- 实验可以复现。

---

### 2.4 val 与 test 的使用

本方案明确不从 `val` 中抽取训练图片。

```text
train -> 只选择少量样本用于训练
val   -> 保持原样，用于训练过程验证
test  -> 保持原样，用于最终独立测试
```

训练规模小并不意味着验证集和测试集必须同步缩小。

由于模型推理的计算量明显低于训练，因此最终可以直接在原始 `test` 上进行评估。

---

### 2.5 患者级数据划分

数据已经完成脱敏，但脱敏和数据泄漏属于两个不同问题。

脱敏用于保护个人身份信息；患者级划分用于避免同一患者或同一次检查同时出现在训练数据和测试数据中，从而导致验证结果过于乐观。

处理方式如下：

1. 如果数据提供匿名患者 ID 或可以可靠解析的匿名检查 ID，则检查 train 与 test 是否存在重复患者；
2. 如果当前公开数据只提供图片和类别目录，没有足够信息重新进行患者级检查，则沿用原数据集 train / val / test 划分；
3. 在最终报告中明确说明无法独立重新验证患者级隔离这一限制；
4. 真实医学影像项目中，应基于匿名 `patient_id` 或 `study_id` 完成患者级划分。

## 3. 辅助信息

### 3.1 选择的辅助信息

本方案选择胸部 X 光检查体位，例如：

```text
AP
PA
```

作为影像之外的一种辅助信息。

不同检查体位可能改变胸部结构在 X 光图像中的投影表现，因此在真实项目中，该字段可以帮助模型或后处理阶段更合理地解释图像差异。

---

### 3.2 当前项目中的使用方式

如果当前 `chest_xray` JPG 数据没有可靠、成对的 AP/PA 元数据，baseline 不强行加入该信息。

Baseline 保持：

```text
X-ray image
     ↓
ResNet18
     ↓
P(NORMAL), P(PNEUMONIA)
```

因此辅助信息缺失不会导致模型无法工作。

---

### 3.3 真实项目中的获取与配对

真实医学影像项目通常可以从影像对应的结构化检查信息或 DICOM 元数据中获得检查体位等字段。

理想流程为：

```text
DICOM image
    +
ViewPosition
    +
study_id
    ↓
按 study_id / image_id 配对
    ↓
图像模型特征 + 结构化辅助信息
    ↓
分类器
```

后续如果获得可靠的成对元数据，可以把 AP/PA 编码后与 ResNet18 提取的图像特征拼接，再进行分类。

---

## 4. 模型思路

## 4.1 为什么选择 2D

本项目优先使用 2D 模型。

原因是当前输入本身是二维胸部 X 光图像，不需要像 CT 或 MRI 体数据一样处理连续切片，因此使用 2.5D 或 3D 模型会增加不必要的复杂度和计算量。

同时，本项目只要求小规模 CPU 验证，因此 2D 网络更适合作为起点。

---

## 4.2 Baseline

Baseline 选择：

```text
ImageNet 预训练 ResNet18
```

主要原因：

1. 结构成熟，容易理解和复现；
2. 有公开预训练权重；
3. 相比大型网络计算量较小；
4. 可以通过迁移学习减少小样本训练需求；
5. 适合 CPU 上完成最小规模验证。

模型结构：

```text
Chest X-ray
     ↓
Resize 224 × 224
     ↓
3-channel input
     ↓
Pretrained ResNet18
     ↓
512-dimensional feature
     ↓
Linear(512, 2)
     ↓
NORMAL / PNEUMONIA
```

---

## 4.3 Baseline 训练策略

第一版不完整微调整个 ResNet18。

先冻结 backbone：

```python
for param in model.parameters():
    param.requires_grad = False
```

然后替换最后的分类层：

```python
model.fc = nn.Linear(model.fc.in_features, 2)
```

只训练新的全连接分类层。

这种方式可以：

- 降低训练计算量；
- 降低小样本过拟合风险；
- 让 CPU 实验更快完成；
- 形成一个容易解释的 baseline。

---

## 4.4 模型输入

模型输入统一为：

```text
224 × 224 × 3
```

如果原始胸部 X 光图像是单通道灰度图，则转换为 3 个相同通道：

```text
Gray
 ↓
[Gray, Gray, Gray]
```

这样可以直接使用针对三通道图像训练的 ImageNet 预训练 ResNet18。

---

## 4.5 预处理

基础预处理包括：

```text
读取图像
  ↓
转换为 RGB / 3 通道
  ↓
Resize 224 × 224
  ↓
转换为 Tensor
  ↓
Normalize
```

第一版不使用复杂医学影像增强方法，避免增加无法清楚解释的变量。

如果需要轻量增强，可以只考虑幅度较小、不会明显破坏医学结构的操作，并在实验中明确记录。

---

## 4.6 输出

模型输出两个类别的 logits：

```text
NORMAL
PNEUMONIA
```

经过 Softmax 可以得到：

```text
P(NORMAL)
P(PNEUMONIA)
```

最终选择概率较高的类别作为图像级预测结果。

保存到 `predictions.csv` 时可以包含：

```text
image_path
true_label
predicted_label
p_normal
p_pneumonia
```

---

## 4.7 类别不平衡处理

完整数据集中两个类别的数量可能不一致。

但是本项目使用小样本训练，因此 baseline 直接从两个类别中等量抽取训练图片：

```text
NORMAL:     300
PNEUMONIA:  300
```

这样 baseline 可以直接使用：

```text
CrossEntropyLoss
```

不额外增加复杂的类别权重。

如果后续扩展到完整训练集，可以再使用：

```text
class weighted CrossEntropyLoss
```

或：

```text
WeightedRandomSampler
```

处理类别数量不平衡问题。

---

## 5. 改进方向

Baseline 只训练最后的分类层。

在 baseline 跑通后，可以进行一个简单的改进实验：

```text
Baseline
冻结整个 ResNet18 backbone
只训练 fc
```

对比：

```text
Improved
冻结前面的网络
解冻 ResNet18 layer4
训练 layer4 + fc
```

设计目的不是构建复杂网络，而是观察：

> 允许预训练模型最后一部分卷积特征适应胸部 X 光数据后，Sensitivity 或 ROC-AUC 是否有所改善。

为了减少过拟合，改进实验可以采用比分类层更小的学习率，并保持训练 epoch 较少。

如果未来获得 AP/PA 等可靠辅助信息，还可以进一步尝试图像特征和结构化信息融合，但该扩展不是当前最小实验必须完成的内容。

---

## 6. 建议训练配置

Baseline 初始配置：

```yaml
model: resnet18
pretrained: true

image_size: 224

train_samples:
  NORMAL: 300
  PNEUMONIA: 300

batch_size: 16
epochs: 3
learning_rate: 0.001

freeze_backbone: true
random_seed: 42
```

如果 CPU 运行较慢，可以：

- 将每类训练图片降低到 200；
- 减少 epoch；
- 降低 batch size。

本实验的目的不是追求最高指标，而是确认完整算法流程可以运行和检查。

---

## 7. 验证方法

### 7.1 指标一：Sensitivity

Sensitivity 用于观察真实 PNEUMONIA 样本中有多少被模型识别出来。

计算方式：

```text
Sensitivity = TP / (TP + FN)
```

对于异常检测任务，漏掉异常样本是一个重要失败类型，因此 Sensitivity 是一个直观的验证指标。

---

### 7.2 指标二：ROC-AUC

ROC-AUC 使用模型输出的肺炎预测概率衡量两个类别的整体区分能力。

相比单独使用 Accuracy，AUC 不依赖某一个固定分类阈值，因此适合作为本项目第二个主要指标。

---

## 8. 最小验证流程

整个验证过程按以下顺序执行：

```text
1. 检查数据目录
        ↓
2. 检查图片是否可以读取
        ↓
3. 统计 NORMAL / PNEUMONIA 数量
        ↓
4. 随机查看若干图像
        ↓
5. 固定抽取少量 train 样本
        ↓
6. 加载预训练 ResNet18
        ↓
7. 冻结 backbone，训练分类层
        ↓
8. 在 val 上查看训练过程
        ↓
9. 在 test 上计算 Sensitivity / ROC-AUC
        ↓
10. 查看正确和错误预测案例
```

该流程能够证明从数据到预测输出的完整链路可以工作。

---

## 9. 成功与失败案例检查

模型测试完成后，不只查看总体指标，还需要人工检查若干样本。

建议至少展示：

```text
正确预测 NORMAL     2~3 张
正确预测 PNEUMONIA  2~3 张
错误预测 NORMAL      2~3 张
错误预测 PNEUMONIA   2~3 张
```

主要观察：

- 图片是否模糊；
- 是否存在曝光异常；
- 胸部区域是否完整；
- 是否存在明显的采集差异；
- 错误是否集中在某种图像类型。

---

## 10. 可能失败的情况与处理

### 10.1 图像质量差

可能情况：

- 模糊；
- 曝光异常；
- 图像裁剪；
- 胸部区域不完整；
- 文件损坏。

处理：

1. 在 `check_dataset.py` 中检查无法读取的文件；
2. 保存异常图片路径；
3. 对明显损坏文件不进入训练；
4. 在报告中记录排除规则；
5. 不通过人工修改标签来“修正”模型结果。

---

### 10.2 数据分布变化

训练数据和真实医院中的数据可能来自不同：

- 医院；
- X 光设备；
- 人群；
- 年龄；
- 检查体位；
- 图像后处理流程。

因此模型在当前 test 上有效，并不代表在其他来源的数据上同样有效。

处理：

- 将当前结果限制为数据集内部验证；
- 如果用于进一步研究，应寻找独立外部数据集进行测试；
- 检查不同来源数据上的性能下降。

---

### 10.3 标签不可靠

公开数据标签可能存在噪声。

例如：

- 标签来自报告自动提取；
- 标签定义不完全一致；
- 图像中可能存在其他异常。

处理：

- 不把单张图像预测解释为医学结论；
- 人工查看部分失败样本；
- 如果后续有专业标注，可以重新验证标签质量。

---

### 10.4 辅助信息缺失

当前 JPG 数据如果没有可靠的 AP/PA 等结构化信息，则无法直接完成多模态融合。

处理：

- baseline 始终保持图像独立推理能力；
- 缺失辅助信息时仍然可以输出预测；
- 把辅助信息融合保留为真实项目或后续扩展方案。

---

### 10.5 小样本过拟合

训练数据只有几百张，即使使用迁移学习也可能过拟合。

处理：

- 冻结大部分 backbone；
- 控制 epoch 数量；
- 使用固定 train 子集；
- 通过 val 观察性能变化；
- 不因为 test 指标不理想而反复调整测试集。

---

## 11. 最小实验结果应该回答的问题

完成实验后，不要求证明模型已经达到临床可用水平，只需要回答：

1. 数据是否可以正常读取？
2. 数据类别是否正确？
3. 小样本是否能够进入模型训练？
4. ResNet18 baseline 是否能够产生合理的预测概率？
5. Sensitivity 和 ROC-AUC 能否正常计算？
6. 成功和失败样本是否能够被人工查看？
7. 简单解冻 `layer4` 后，结果是否发生变化？
8. 当前方案存在哪些明显限制？

只要这些问题能够被回答，就完成了本项目最核心的工程验证目标。
