# 胸部 X 光 NORMAL / PNEUMONIA 二分类算法方案

> 方案版本：2026-09-07，已依据本方案完成纯图像实现与真实实验。  
> 实施状态：数据审计、清单处理、冻结 ResNet18 + 逻辑回归、最终测试、案例分析与单图预测均已完成；详见 `readme.md` 和 `reports/`。  
> 下文第 1–5.3 节保留设计时的“拟采用／计划”表述，用于追溯原始约定；实际配置与结果以第 5.4 节及 README 为准。多模态实验、数据来源许可及患者级独立性仍未核实或未开展。

## 1. 任务定义

### 1.1 问题、输入、输出与用途

本项目研究用户已下载的公开胸部 X 光图片包中的 `NORMAL / PNEUMONIA` 图像级二分类问题。输入为单张二维胸部 X 光图像，输出为两个数据集类别的预测分数及按照预定阈值得到的预测类别。项目首先完成数据读取、标签组织和划分风险检查，再选择是否运行 CPU 基线。结果用于验证分类流程、比较方案和分析与数据集标签不一致的样本，不用于诊断、治疗或实际临床决策。

### 1.2 任务边界

选择题目“检测”方向中的**类别判断**，不同时开展病灶定位、分割或图像生成。[S1] 标签约定为 `NORMAL=0`、`PNEUMONIA=1`。

模型只处理图像像素。文件路径、类别目录、文件名中的 `person`、`virus / bacteria` 等内容仅用于样本管理和检查，不作为特征。项目不识别患者真实身份，不推断病毒或细菌亚型，不生成诊断报告，也不建设前端、数据库或临床部署系统。

`NORMAL` 是本数据集的类别名称，不等于排除所有疾病；分类器的预测分数也不能直接解释为真实患病概率。

### 2.4 候选分组：有线索，但尚未核实患者含义

根据截图，先采用下列文件名启发式规则进行排查：[S2][S3]

| 文件名示例 | 候选分组 | 含义 |
|---|---|---|
| `person1_virus_6.jpeg`、`person1_virus_7.jpeg` | `person1` | 提取 `person` 后的数字，不把后续图像编号当患者编号 |
| `person3_virus_15.jpeg`、`person3_virus_16.jpeg` | `person3` | 检查同一前缀是否跨集合出现 |
| `IM-0011-0001.jpeg`、`IM-0011-0001-0002.jpeg` | `IM-0011` | 同一 `IM` 前缀下的候选关联组 |
| 不符合脚本规则的名字 | 空值 | 标为 `unmatched`，不强行猜测编号 |

脚本还支持 `person<数字>_bacteria_<数字>`，其分组不包含 `virus / bacteria` 字样；若出现 `NORMAL2-IM-…` 等受支持命名，会保留独立前缀命名空间，不直接与 `IM-…` 合并。这些是程序能力，不表示已在截图中确认出现了所有命名形式。

分组键也不包含 `train / val / test`，否则同一前缀跨集合出现的现象会被人为掩盖。

必须保留以下限制：

- 相同前缀可能属于同一患者或同一次检查，也可能发生命名冲突。
- 不同前缀不能证明患者不同；文件不重复也不能证明患者独立。
- `patient_id_verified=False` 与 `patient_level_isolation_verified=False` 是当前脚本的固定状态，不能通过“没有重叠”自动改成已验证。

患者信息已脱敏，不妨碍使用**经过可靠说明的稳定匿名编号**进行分组；但本项目不恢复真实身份，也不把未经核实的前缀伪装成可靠患者 ID。

### 2.5 划分方案与正式评估前提

**先检查原始划分，不先把全部图片打散。** 原始 `train` 用于拟合，`val` 用于选择参数或阈值，`test` 留作最终评估；这是一项使用约定，不是对原始划分质量的认证。

拟按以下顺序处理：

1. 检查跨集合的字节重复、像素重复和候选分组重叠，并核实原始数据的划分说明。
2. 获得可信匿名患者／检查标识时，以患者为优先分组单位；同一患者的图片不跨训练、验证和测试。分配时尽量保持类别比例，记录规则和随机种子。
3. 原始验证集是否足够，依据实际统计判断。需要另划验证集时，仅从训练开发部分按可靠分组划出，测试集保持独立，不按图片随意随机切分。
4. 发现重复、标签冲突或可疑跨集合关联时，先建立明确的复核和排除规则，记录处理前后的清单与数量，不根据模型分数决定保留哪些样本。
5. 无可靠匿名标识或可信划分证据时，可保留原始集合做有限流程实验；按候选前缀进行的隔离也只能称“启发式分组”，不能报告为严格患者独立评估。

测试集不得参与特征标准化参数拟合、分类器训练、参数选择或阈值调整。小样本尝试也应在划分确定后从各集合内部取样；有可靠分组时，以组为单位选样并保留记录。

题目要求同一患者或同一次检查不能跨训练与测试。[S1] **这一要求目前仍有待证据核实；写出规则或运行哈希检查，都不等于已验证本数据集满足要求。**

### 2.6 辅助信息的当前状态

当前没有配对辅助信息，因此实际实现不依赖额外字段。后续扩展选择“检查申请时已经存在的结构化症状记录”，具体获得、配对、接入和缺失处理见第 4 节。题目允许在没有成对数据时说明真实项目的获取与配对方式，也允许仅将其作为扩展设计。[S1]

## 3. 模型思路

### 3.1 基线选择与理由

拟采用：

**ImageNet 预训练 ResNet18 固定特征提取器 + 逻辑回归分类器。**

固定卷积网络参数，移除或绕过原始 ImageNet 分类头，提取图像特征，再用当前数据的训练标签拟合一个二分类器。采用该方案是为了将图片读取、预处理、特征提取和分类器拆开检查，减少第一版需要训练的参数与工程复杂度。[T1]

ImageNet 预训练权重并不是现成的肺炎分类器，其原始类别输出不能直接作为本项目结果。采用迁移特征是否有效，需要本项目数据上的实验验证；当前不预设其 AUC、召回率或运行时长。

相比从头训练深度网络，本方案更适合作为可解释、可检查的起点。它仍会消耗 CPU 时间，首次取得权重也可能需要下载；“不训练特征提取器”不等于没有计算成本。

### 3.2 为什么选择 2D

输入是单张二维胸片，当前没有已核实的体数据、连续切片或同一检查下可靠配准的多张图像，因此第一版选择 **2D**。不从无序文件构造 2.5D 或 3D 输入，也不把同一候选前缀下的图片默认当作可拼接的连续切片。

### 3.3 输入、预处理和输出

以下是**待实现的处理约定**，不是当前审计脚本已经执行的图像变换。

```text
单张原始图像
    ↓
读取并检查模式、方向和完整性
    ↓
统一灰度表示，复制为三通道
    ↓
等比例缩放并补边至固定尺寸
    ↓
按照选定预训练权重要求进行数值归一化
    ↓
固定的 ResNet18 特征提取器
    ↓
特征标准化 + 逻辑回归
    ↓
PNEUMONIA 分数 + 阈值分类
```

预处理拟保留完整视野，不在第一版使用随机裁剪、强旋转或复杂增强。固定尺寸、插值方式、补边方式和权重版本在实现时写入配置；具体取值尚未通过实验确认。缩放与补边是本项目拟采用的几何处理，应与权重自带变换区分，不能未经检查又叠加一次中心裁剪。

三通道表示只是为了匹配特征提取器输入，不代表有三个独立影像模态。无法可靠解释的高位深、多帧或异常模式图像应单独复核，不静默压缩或转换后混入训练。

训练和评估使用一致、可追溯的预处理。检查原图与处理后的样例，确认方向没有意外变化，重要视野没有被裁掉。

拟输出字段包括图像标识、真实数据集标签、`pneumonia_score`、使用阈值和 `predicted_label`。默认方案先固定阈值为 `0.5`；需要调整时只能在验证集上完成并在最终测试前锁定。这个数值是工程起点，不是临床界值。

### 3.4 类别不平衡与小目标处理

根据训练集实际统计判断类别是否不平衡。第一版选择一个简单办法：逻辑回归设置 `class_weight="balanced"`，类别权重仅由训练部分的标签确定，不由验证集或测试集计算。[T2]

本任务不输出病灶框或分割掩码，也不额外设计小目标损失。模型可能难以利用细小异常线索，这是需要通过失败案例分析记录的局限，不通过扩展任务来掩盖。

特征标准化如被采用，只在训练特征上拟合；验证和测试仅使用同一变换。特征提取器保持冻结和评估模式，避免在提取测试特征时更新内部统计。

### 3.5 概念伪代码

下面用于说明步骤，不是已经提供的可执行训练脚本：

```text
加载完成检查的样本清单，保留原始集合和处理记录
核实患者／检查分组或标注划分限制
锁定训练、验证、测试清单

加载指定版本的 ImageNet 预训练 ResNet18
移除原始分类头，冻结参数，设置为评估模式

在验证集上检查分数与错误案例
按事先约定固定参数和阈值

不再拟合任何参数，执行最终测试
计算 ROC-AUC 和 PNEUMONIA 召回率
保存样本级预测、混淆计数与错误分析
```

### 3.6 单一改进方向

在纯图像基线之后，唯一优先讨论的改进方向是加入真实、检查前可用的结构化症状信息。当前不同时增加复杂网络、三维结构、生成增强、知识图谱或报告生成。没有配对数据时，这个改进保留为设计，不报告增益。

## 4. 辅助信息扩展

### 4.1 信息选择与预期作用

选择检查申请时的结构化记录，例如发热、咳嗽是否被记录。它们可能提供图像之外的背景信息，但能否帮助当前分类任务属于待验证假设，不保证提升效果。

以下是未来数据接口的设计示例，不是当前图片包已有字段：

| 字段 | 设计用途 |
|---|---|
| `anonymous_patient_id` | 经可靠说明的稳定匿名患者标识，用于配对与分组，不输入模型 |
| `exam_id` | 检查级配对标识，不输入模型 |
| `exam_time`、`record_time` | 检查信息在预测时是否已存在，避免使用事后记录 |
| `fever`、`cough` | 结构化症状值；至少区分是、否、缺失 |
| `aux_available` | 配对辅助信息是否可用 |
| 对应字段的缺失标记 | 区分未记录、未测量与明确否定 |

### 4.2 获取和配对方式

真实项目中，在获得授权且使用条件清楚的前提下，由合规数据流程从检查申请或相应结构化记录中导出信息，并进行规范去标识化。图像和辅助记录必须共享可信的匿名映射规则。

配对时同时核对患者关联、检查编号和时间关系；不能仅凭大致日期或相同姓名匹配。同一患者多次检查时，优先使用明确的检查级对应关系。只采用在预定预测时点已经可用的记录，不使用影像阅片后的诊断结论、出院诊断或从类别标签反推的内容。

多对一、冲突、时间不一致或无法确认的配对单独记录，不强行选一条记录接入模型。原始身份映射不进入本项目样本清单或模型输入。

### 4.3 如何参与模型与如何比较

未来具备真实配对数据后，拟将症状值及缺失标记编码成小型结构化向量，与图像特征拼接，再训练轻量分类器。所有需拟合的编码、填补和标准化步骤只使用训练部分。

在相同患者、相同图像、相同划分和相同评估规则上比较“仅图像”与“图像 + 辅助信息”。同时报告辅助信息覆盖情况，避免把两个不同样本群体的指标差异当成多模态增益。

### 4.4 缺失和不可靠时如何继续

完全缺少辅助信息或配对不可靠时，直接使用独立的纯图像基线，标记 `aux_available=false`。部分字段缺失时使用明确的缺失编码，不能把空值自动当成“没有症状”。

不按 `NORMAL / PNEUMONIA` 标签生成症状，不用文件名中的 `virus / bacteria` 充当辅助信息，也不把由标签或当前图像生成的模拟报告宣称为真实、独立的临床记录。

本次只提交这部分设计，不提交虚构的配对表，不声称验证了多模态效果。

## 5. 验证方法

### 5.1 两个主要指标

将 `PNEUMONIA` 定义为正类，使用以下两项指标：

| 指标 | 作用 | 计算与解释约定 |
|---|---|---|
| ROC-AUC | 观察连续分数对两个数据集类别的区分能力 | 使用连续分数而非硬标签；评估集合必须同时含两类 |
| PNEUMONIA 灵敏度／召回率 | 观察带该标签的样本有多少被识别 | `TP / (TP + FN)`；阈值在测试前锁定 |

ROC-AUC 不代表分数已经校准，也不直接给出某一阈值下的漏检数。单独提高召回率也可能伴随更多误报，因此同时保留 `TP / FP / TN / FN` 混淆计数作为结果解释材料，不再额外堆叠主要指标。

只有单一类别时，ROC-AUC 标记为不可计算并说明原因；没有正类时，正类召回率也标记为不可计算。不能用 `0`、`1` 或其他看似正常的数值代替这些情况。

### 5.2 最小验证流程

| 阶段 | 操作 | 可检查证据 |
|---|---|---|
| 1. 数据可读性 | 执行检查脚本，查看尺寸、模式与异常 | 样本清单、汇总和异常记录 |
| 2. 标签与划分 | 核对目录标签，检查重复与候选分组，追查来源说明 | 重复报告、分组报告、划分处理记录 |
| 3. 基线分析或运行 | 至少解释固定特征与分类器流程；条件允许时运行 CPU 小样本实验 | 分析说明；或实际运行的配置和日志 |
| 4. 指标计算 | 使用锁定的模型、预处理与阈值评估 | 实际分数、两项指标及混淆计数 |
| 5. 样例复核 | 查看若干正确、漏报与误报样例 | 样例索引、预测与工程原因分析 |

对于仅提交方案与检查脚本的版本，第 3 阶段可以完成基线分析而不训练；第 4、5 阶段的模型结果保持待完成，不用模拟预测冒充实验。模型成功与失败案例只有在实际运行后才建立；在此之前只能提供图片读取或其他工程检查案例。

### 5.3 成功与失败案例的查看原则

实际运行后，固定一组抽样或排序规则，分别查看预测正确的样例、带 `PNEUMONIA` 标签但被预测为 `NORMAL` 的样例，以及相反的误报样例。保存相对路径、原始标签、预测分数、类别和问题描述；展示图片需满足相应使用条件。

重点检查方向、补边、裁剪、亮度、异常模式、重复线索和标签来源。不因个人看图判断或模型高置信度预测而擅自宣布医学标签错误。

最终测试后的错误分析用于说明局限。若据此修改方案，再次使用同一测试集时应披露它已被用于开发反馈，不能继续把它当作完全未使用过的独立评估。

## 6. 可能失败的情况与处理方式

以下为设计时考虑的风险，不表示已经在用户数据中全部发现。

| 风险 | 如何发现 | 处理方式 |
|---|---|---|
| 图片损坏、异常模式、多帧或视野处理不当 | 解码记录、尺寸和模式统计、原图与处理后图像对照 | 记录问题；按预先确定的规则隔离或处理，不静默转换并混入训练 |
| 同一图片或相关患者样本跨集合出现 | 字节／像素重复、候选前缀重叠、可靠匿名关联与来源说明 | 暂停独立评估结论；核实并保存处理后的清单，不只依赖随机图片划分 |
| 标签不一致或来源不可靠 | 相同图片标签冲突、来源记录缺失、错误案例复核 | 追查标注依据；无法澄清时隔离并披露，不自行做医学重标注 |
| 验证集过小、类别不平衡 | 真实类别数量、验证结果不稳定或指标无法计算 | 优先在训练开发部分按可靠分组调整验证方案；训练使用类别权重；保留测试集 |
| 新来源或新设备图像与开发数据不同 | 对比来源与预处理分布，按来源单独检查和评估 | 不直接外推既有结果；先进行新来源验证，报告适用范围 |
| 辅助信息缺失、时间不对或配错检查 | 配对键、时间关系、冲突和缺失率检查 | 不接入不可靠记录；回退到纯图像基线 |
| 文件名或事后信息泄漏标签 | 检查输入字段、数据处理和特征生成流程 | 模型只读取允许的信息；排除路径、文件名与事后诊断线索 |

现有脚本不能覆盖全部风险。尤其是近似图像、重复检查、跨命名空间患者关联、脱敏与医学标签问题，需要额外证据或人工复核；无法核实时降低结论范围，而不是将未知写成“通过”。
