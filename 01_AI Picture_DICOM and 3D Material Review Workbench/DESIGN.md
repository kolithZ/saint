# DESIGN.md

# 基于胸部 X 光影像的肺炎二分类与多模态扩展方案

## 1. 任务定义

本项目选择胸部 X 光影像的二分类作为主任务，目标是根据单张胸部 X 光图像区分 `NORMAL` 与 `PNEUMONIA` 两类标签。

输入为一张胸部 X 光影像；输出为 `NORMAL` 或 `PNEUMONIA` 的预测类别，以及对应的模型预测分数。项目首先实现一个仅使用影像的 2D 分类基线，再设计加入 WBC（白细胞计数）与 CRP（C 反应蛋白）结构化检验信息的多模态改进方向。

本项目仅用于算法研发、工程验证和课程任务展示，不作为临床诊断、治疗或医疗决策依据。

## 2. 数据

### 2.1 当前数据结构

当前解压后的数据目录中已经确认存在：

```text
chest_xray/
├── train/
│   ├── NORMAL/
│   └── PNEUMONIA/
├── val/
└── test/
```

压缩包中还存在 `__MACOSX` 目录以及重复的 `train / val / test` 目录。`__MACOSX` 属于 macOS 压缩产生的元数据目录，不参与实验。正式运行前需要通过脚本确认两套目录是否重复，并只保留或指定其中一套作为数据源。

### 2.2 数据来源

当前目录结构与公开的 Chest X-ray Pneumonia 类数据集一致，但最终提交前仍需补充并核实以下信息：

- 数据集正式名称；
- 数据下载页面或原始发布地址；
- 影像来源机构；
- 许可或使用条件；
- 是否为公开、去标识化数据；
- 是否提供患者 ID、检查 ID 或其他可用于患者级划分的信息。

> TODO：这里不要仅根据文件夹名称推断来源。应以实际下载页面或数据说明为准。

### 2.3 标签

当前已经从目录确认两个影像标签：

- `NORMAL`
- `PNEUMONIA`

本项目只进行这两个标签的二分类，不进一步把肺炎分成细菌性、病毒性等子类。

### 2.4 小样本实验规模

为了满足“可检查的最小验证”目标，本项目不使用全部训练数据，而采用小样本训练。

计划如下：

| 数据用途 | NORMAL | PNEUMONIA | 合计 |
|---|---:|---:|---:|
| Train | 300 | 300 | 600 |
| Validation | 50 | 50 | 100 |
| Test | 使用原始 `test/` | 使用原始 `test/` | 以脚本统计结果为准 |

训练集与验证集从原始 `train/` 中抽取。

使用等量的 `NORMAL` 与 `PNEUMONIA` 主要是为了让小样本验证过程更容易解释，并降低类别数量差异对最小实验的干扰。

测试阶段优先保留数据集自带的原始 `test/`，因为测试只需要前向推理，计算成本较低，同时比继续缩小测试集更有利于获得相对稳定的 AUC 和 Sensitivity。

### 2.5 数据划分原则

理想情况下，训练、验证和测试应按照患者或检查进行划分，保证同一患者或同一次检查的数据不会跨越不同集合。

如果数据集能够提供患者 ID、检查 ID 或可以可靠解析出的患者标识，则使用 Group Split。

如果当前公开数据中没有可靠的患者标识，则：

1. 保留数据集原始 `test/` 作为最终测试集；
2. 从原始 `train/` 中随机抽取训练和验证样本；
3. 在文档中明确说明目前无法独立验证患者级重叠；
4. 将“患者级数据泄漏风险”列为当前方案的限制；
5. 在真实项目中必须通过 patient ID / study ID / encounter ID 进行分组划分。

### 2.6 数据检查

训练前至少检查：

- 图像是否能够正常读取；
- 每个 split 中各类别样本数量；
- 图像尺寸分布；
- 灰度/RGB 通道情况；
- 是否存在损坏文件；
- train / val / test 之间是否存在完全相同的图片；
- 是否存在明显异常的图像质量。

建议提供 `inspect_dataset.py` 作为最小可检查产物之一。

## 3. 基线模型

### 3.1 模型选择

基线模型选择：

**ImageNet 预训练 ResNet18 + 线性分类层**

选择原因：

1. 胸部 X 光是二维影像，优先采用 2D 模型即可；
2. ResNet18 结构成熟、实现简单；
3. 参数规模相对较小；
4. 可以利用预训练权重进行迁移学习；
5. 对本项目的小样本和 CPU 验证更友好；
6. 适合作为后续多模态方案的影像特征提取器。

本项目不使用 2.5D 或 3D 模型，因为当前输入是单张二维胸部 X 光影像，而不是 CT/MRI 连续切片。

### 3.2 输入与输出

输入：

```text
单张 Chest X-ray
```

预处理后输入模型。

输出：

```text
P(NORMAL)
P(PNEUMONIA)
```

最终根据概率得到预测类别。

### 3.3 预处理

基础预处理流程：

```text
JPEG / image
    ↓
读取并检查
    ↓
Resize 到 224 × 224
    ↓
灰度图转换/复制为 3 通道
    ↓
Normalization
    ↓
ResNet18
```

训练时可以使用轻量数据增强，例如：

- 小角度旋转；
- 轻微平移；
- 轻微亮度或对比度变化。

数据增强应保持克制，避免产生不符合医学影像实际分布的图像。

### 3.4 小样本训练策略

为了降低 CPU 训练成本，第一版采用：

- ResNet18 预训练权重；
- 冻结 backbone；
- 仅训练最后的分类层；
- 输入尺寸：224 × 224；
- batch size：16；
- epoch：3～5；
- optimizer：Adam；
- 初始 learning rate：0.001。

本实验的目标不是获得临床级准确率，而是验证完整流程能够运行，并观察模型是否能够从小样本中学习到一定的区分信息。

### 3.5 类别不平衡

原始数据可能存在 `NORMAL` 与 `PNEUMONIA` 数量不平衡。

本次小样本实验通过两个类别等量抽样：

```text
NORMAL : PNEUMONIA = 1 : 1
```

降低类别不平衡对最小验证的影响。

如果未来使用完整训练数据，则优先考虑：

- Weighted Cross Entropy；
- 或 WeightedRandomSampler。

本项目第一版不需要同时实现多种不平衡处理方法。

## 4. 辅助信息与多模态改进

### 4.1 辅助信息选择

本项目选择以下结构化检验数据作为辅助信息：

- WBC：白细胞计数；
- CRP：C 反应蛋白。

胸部 X 光主要提供肺部影像形态信息，而 WBC 和 CRP 可提供炎症相关的结构化信息，两类信息具有一定互补性。

WBC/CRP 只能作为辅助输入，不能单独用于决定肺炎标签。

### 4.2 当前数据中的限制

当前使用的公开影像目录中尚未发现与每张 X 光逐一配对的 WBC/CRP 数据，因此：

**本次实际小样本实验只运行 image-only baseline。**

WBC/CRP 多模态融合只作为后续改进方案，不伪造辅助信息，也不使用人工随机生成的“临床数据”来证明多模态效果。

### 4.3 真实项目中的数据配对

真实项目中，影像和实验室检验数据应来自合法、去标识化的数据源，并通过以下信息进行关联：

- Patient ID；
- Encounter ID；
- Study ID；
- Examination Time / Laboratory Time。

可采用的配对原则：

> 优先选择与胸部 X 光属于同一次就诊，并且时间上最接近的 WBC 和 CRP 检验结果。

需要预先定义合理的时间窗口，并防止使用影像检查之后才产生、且在真实预测时不可获得的信息，避免时间泄漏。

### 4.4 多模态融合方式

影像分支：

```text
Chest X-ray
    ↓
ResNet18
    ↓
Image Feature
```

结构化分支：

```text
WBC
CRP
 ↓
标准化
 ↓
Structured Feature
```

然后进行特征拼接：

```text
Image Feature + WBC + CRP
            ↓
      Feature Fusion
            ↓
      Classification
            ↓
 NORMAL / PNEUMONIA
```

一种简单实现方式是：

1. ResNet18 提取约 512 维影像特征；
2. WBC 和 CRP 使用训练集统计量进行标准化；
3. 将二者与影像特征拼接；
4. 输入线性层或小型 MLP；
5. 输出二分类概率。

### 4.5 辅助信息缺失

WBC/CRP 不是模型运行的必要条件。

第一阶段最简单的处理方式：

```text
有 WBC / CRP
    ↓
多模态模型

无 WBC / CRP
    ↓
image-only ResNet18
```

如果未来需要实现统一的多模态模型，可以增加：

- `WBC_missing`
- `CRP_missing`

等缺失标志，并对缺失值采用固定策略填充。

## 5. 验证方法

### 5.1 主要指标

本项目优先使用两个指标：

#### AUC

用于评价模型区分 `NORMAL` 和 `PNEUMONIA` 的整体能力，并减少固定阈值对评价结果的影响。

#### Sensitivity / Recall

以 `PNEUMONIA` 为阳性类：

\[
Sensitivity = \frac{TP}{TP + FN}
\]

用于观察带有 `PNEUMONIA` 标签的样本中有多少被模型识别出来。

Accuracy 可以作为附加统计，但不作为主要评价指标。

### 5.2 最小验证流程

```text
1. 检查数据目录
        ↓
2. 统计各类别数量
        ↓
3. 检查损坏图片、尺寸和通道
        ↓
4. 随机显示 NORMAL / PNEUMONIA 样本
        ↓
5. 生成 300+300 的训练子集
        ↓
6. 生成 50+50 的验证子集
        ↓
7. 加载预训练 ResNet18
        ↓
8. 冻结 backbone，训练分类层 3～5 epoch
        ↓
9. 在 validation 上观察 loss / AUC
        ↓
10. 在原始 test 上计算 AUC / Sensitivity
        ↓
11. 查看若干正确和错误预测样本
```

### 5.3 成功与失败案例检查

至少展示：

- 正确预测的 `NORMAL` 样本；
- 正确预测的 `PNEUMONIA` 样本；
- False Positive；
- False Negative。

建议每种选择 1～2 张用于人工检查。

重点观察：

- 是否存在曝光异常；
- 是否有裁剪、旋转或文本标记；
- 错误是否集中在某类图像质量；
- 模型是否可能依赖非肺部区域的伪特征。

## 6. 可能失败的情况与处理

### 6.1 图像质量差或采集方式不同

问题：

影像曝光、分辨率、设备或采集条件不同，可能导致模型性能下降。

处理：

- 在数据检查阶段统计和可视化异常样本；
- 使用一致的 resize 和 normalization；
- 对明显损坏的图片进行记录或排除；
- 未来在外部数据集上验证泛化能力。

### 6.2 标签不可靠

问题：

公开数据标签可能存在噪声，模型错误不一定完全来自模型本身。

处理：

- 人工查看部分失败案例；
- 不把数据集标签等同于临床确诊；
- 在报告中明确标签质量限制；
- 真实项目应由合格的数据标注流程或临床专家审核。

### 6.3 患者级数据泄漏

问题：

如果没有可靠 patient ID，无法完全保证同一患者不会同时出现在训练和测试中。

处理：

- 优先使用数据集原始 test；
- 检查重复文件；
- 明确记录限制；
- 有 patient ID 时改用 Group Split。

### 6.4 辅助信息缺失

问题：

公开数据没有与影像配对的 WBC/CRP。

处理：

- 当前实验只使用影像；
- 不伪造临床数据；
- 多模态部分只作为方案设计；
- 真实项目中通过同一次就诊信息进行配对；
- 缺失辅助数据时回退到 image-only 模型。

### 6.5 小样本结果不稳定

问题：

本实验训练样本只有 600 张，随机抽样可能明显影响最终指标。

处理：

- 固定 random seed；
- 保存抽样文件列表；
- 明确说明结果属于小样本工程验证；
- 如果时间允许，可以使用不同 seed 重复 2～3 次，报告均值或波动范围。

## 7. 最小可检查产物

建议项目至少提供：

### `inspect_dataset.py`

功能：

- 统计 train / val / test；
- 统计 NORMAL / PNEUMONIA；
- 检查损坏图片；
- 统计尺寸和通道；
- 检查完全重复文件；
- 随机显示样本。

### `make_subset.py`

功能：

- 固定随机种子；
- 从原始 train 中抽取：
  - NORMAL 350；
  - PNEUMONIA 350；
- 再划分：
  - Train：300 + 300；
  - Validation：50 + 50；
- 保存抽样清单，保证实验可复现。

### `train.py`

功能：

- 加载预训练 ResNet18；
- 冻结 backbone；
- 替换最后分类层；
- 小样本训练；
- 保存训练日志；
- 计算 validation 指标。

### `evaluate.py`

功能：

- 在原始 test 上运行 inference；
- 计算 AUC；
- 计算 Sensitivity；
- 保存预测结果；
- 输出成功和失败样本列表。

## 10. 当前方案结论

当前确定的核心方案为：

```text
主任务：
Chest X-ray NORMAL / PNEUMONIA 二分类

实际实验：
300 NORMAL + 300 PNEUMONIA 训练
50 NORMAL + 50 PNEUMONIA 验证
原始 test 最终测试

基线：
2D ResNet18 pretrained
冻结 backbone
只训练分类层
3～5 epoch

主要指标：
AUC
Sensitivity

辅助信息：
WBC + CRP

多模态状态：
作为后续扩展设计
当前公开数据无配对信息，因此不参与实际小样本训练
```

本方案的重点是建立一个规模小、能够运行、能够解释、能够检查的数据与模型验证流程，而不是追求完整训练或临床级性能。
